## 이번에 바뀐 것 (사용자가 승인한 8차 수정)

1. **[내 그림] 넣기·붙여넣기**: 사용자가 앱에서 자기 그림을 넣는다(사용자가 고른 방식 A: 덱 안에 저장).
   - `deck-spec.js`: 덱의 `images`(`{ id: data 주소 }`), 슬라이드에서는 `user:<id>`로 가리킴. `USER_IMG_ID`, `USER_IMG_DATA`(png·jpeg·webp base64만), `MAX_USER_IMAGES`(60), `MAX_USER_IMG_CHARS`(300만 자), `isUserImgData`, `userImgId`. `sanitize`가 `images`를 걸러 내고, 그림 칸(`img`)·스티커는 `images`에 있는 `user:` 경로만 받음.
   - `app.js` 「내 그림」 구간: 파일을 캔버스로 다시 그려 긴 쪽 1600px로 줄임(투명하면 PNG, 아니면 JPEG 0.85, 제한을 넘으면 0.75배씩 더 줄임). 화면에는 Blob 주소(`userImgURL`, 캐시). `placeUserImage`는 바로 저장해 보고, 저장 공간이 모자라 실패하면 넣은 것을 되돌리고 알림. 같은 그림은 다시 넣지 않고 재사용. `deleteUserImage`는 그 그림을 쓴 그림 칸·스티커에서도 뺌.
   - 붙여넣기: 문서 캡처 단계 `paste`. 편집 모드에서 클립보드에 그림 파일이 있으면 넣음. 글자 칸 편집 중이고 글자가 있으면 글자 붙여넣기에 양보(워드·한글이 그림도 함께 실어 보내서). 그림 칸 고르기 창이 열려 있으면 그림 칸에.
   - 스티커 창에 [내 그림] 탭, [＋ 그림 추가](`#fileUserImg`), 그림마다 ✕.
2. **[? 도움말]**: 도구 줄 버튼과 `#helpPanel`. 자동 저장, ① [폴더에 저장], ② [저장]→[불러오기], 그림이 어디에 들어가는지. 맨 위 `#helpNow`는 발표 폴더인지(`PACK`)와 `showDirectoryPicker` 지원 여부로 문구를 고름. Esc와 다른 패널과 서로 닫힘.
3. 문서: `app/README.md`, 스킬 문서 두 벌(같은 내용, `images`·`user:`는 그대로 두라는 안내), AGENTS.md 버전.

Claude가 확인한 것(헤드리스 Chrome): 3000x2000 그림이 JPEG로 줄어 들어감, 투명 PNG 붙여넣기(ClipboardEvent+DataTransfer)가 PNG로 들어감, [내 그림] 탭 목록과 그림 칸 넣기(Blob 주소로 그려짐), `sanitize` 왕복, SVG data 주소와 없는 `user:` 경로가 버려짐, ✕로 지우면 쓰인 곳에서도 빠짐, 저장 공간을 채운 뒤 넣으면 되돌리고 알림, 그림이 든 덱으로 `pack-deck` 발표 폴더를 만들어 인쇄 펼침·`preview-deck` 캡처에 그림이 보임, 기본 덱 13장 캡처가 수정 전과 같음, 도움말·[내 그림] 화면 캡처.

## 지시 사항 (검토만 한다)

- **소스 파일을 고치지 않는다.** 의견과 수정 제안만 보고서에 적는다.
- **Chrome은 실행하지 않는다.** 코드 읽기와 Node 격리 실행으로만 확인한다.
- **텔레그램 등 밖으로 아무것도 보내지 않는다.**
- `decks/`의 파일과 바탕화면은 읽기만 한다. 스크립트를 시험하려면 임시 폴더를 쓰고 `decks/생성기록.json` 변경은 되돌린다.

중점적으로 볼 것:
- 보안: `images`의 data 주소와 `user:` 경로가 HTML 속성(`src`)으로 들어가는 길, `sanitize`를 거치지 않는 길(붙여넣기, [불러오기], `deck-data.js`, 브라우저 저장본), 정규식 비용(300만 자)
- 저장 공간: 되돌리기 조건(`wasFailing`), 되돌린 뒤 상태(선택, 그림 칸), 여러 장을 한 번에 넣다 중간에 실패할 때
- Blob 주소 캐시: 해제 시점, [불러오기]·[초기화]로 덱이 바뀔 때, 인쇄 중
- 붙여넣기 조건: 글자 칸·입력창·발표 모드·패널이 열려 있을 때, 그림과 글자가 함께 있을 때
- 지우기: 쓰인 곳 세기, 선택 해제, 빈 `images` 정리
- 도움말 문구가 실제 동작과 맞는지, README·스킬 문서와 코드가 맞는지
