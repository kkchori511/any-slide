## 앱 개요

- 순수 HTML/CSS/JS 슬라이드 발표 앱: `app/index.html`, `app/style.css`, `app/app.js`. 빌드 도구 없음, 브라우저에서 `index.html`을 열면 동작.
- 슬라이드 6종: 표지, 본문, 설명(말풍선), 챕터 A, 챕터 B, 종료. 기준 이미지는 `내캐릭터_깨끗한아이보리메인_슬라이드6종_2026-10-20_v02/01_슬라이드PNG_1920x1080_깨끗한아이보리/`의 PNG 6장이다.
- 기능: 편집 모드(글자를 클릭해 바로 수정), 애니메이션(글자 페이드인, 팝, 둥실둥실), 발표 모드(전체 화면), 스티커 추가/이동/크기 조절/삭제, 덱 저장(JSON)과 불러오기, localStorage 자동 저장.
- 스타일 규칙은 `docs/핵심브리프_스티커에셋.md`를 따른다.

## 지시 사항 (검토만 한다)

**소스 파일을 직접 고치지 않는다.** 의견과 수정 제안만 보고서에 적는다. 수정은 내가 한다.

1. `app/app.js`, `app/style.css`, `app/index.html`을 끝까지 읽는다.
2. 아래 관점으로 버그와 위험을 찾는다. 실제로 재현되는 문제와 코드 읽기만으로 의심되는 문제를 구분한다.
   - 데이터 손실: 편집 중 글자가 날아가거나 저장되지 않는 경우, localStorage 파싱/저장 오류, 불러오기 실패 처리
   - 편집 모드: `contenteditable="plaintext-only"` 지원 여부(Chrome, Safari, Firefox), 줄바꿈 처리, 입력 중 포커스와 커서 유지
   - 스티커: 드래그와 크기 조절(포인터 이벤트), 선택/삭제 상태, 애니메이션 중 조작, 화면 밖으로 나간 스티커
   - 발표 모드: 전체 화면 진입과 종료(Esc), 키보드/클릭 이동, 커서 숨김, 창 크기 변경 시 배율
   - 애니메이션: 슬라이드 이동 때마다 재생되는지, 애니메이션 끄기와 `prefers-reduced-motion` 처리
   - 접근성과 사용성: 키보드 조작, 포커스 표시, 한글 입력(IME) 중 단축키 충돌
   - 코드 품질: 중복, 죽은 코드, 이상한 분기, XSS 가능성(JSON 불러오기로 들어오는 값 포함)
3. 가능하면 직접 브라우저(headless Chrome 등)로 열어서 확인한다. 예: `file://.../app/index.html#s=3&view`는 3번 슬라이드를 발표 화면으로 연다.
4. 디자인 면: `app/`이 렌더링한 6종 슬라이드가 기준 PNG와 얼마나 다른지(글자 위치, 크기, 캐릭터와 소품 위치) 눈으로 비교하고, 눈에 띄는 차이를 적는다.
5. 앱 구조와 기능에 대해 네 의견(개선 제안, 놓친 기능, 위험)도 적는다.
