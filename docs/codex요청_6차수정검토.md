## 이번에 바뀐 것 (사용자가 승인한 6차 수정)

1. **발표 폴더 이름에 발표 날짜**: `pack-deck.mjs`가 폴더를 `<날짜>_<제목>_v<버전>`으로 만든다. 날짜는 `--date YYYY-MM-DD`, 없으면 덱 파일 이름 앞의 `YYYY-MM-DD_`. 둘 다 없으면 날짜 없이 만들고 알린다. 버전은 전처럼 같은 제목으로 만든 횟수. 덱 JSON도 `<폴더 이름>.json`, `deck-data.js`의 pack에 `name`을 넣고, 생성 기록에 `presentDate`.
   - `app.js`의 `packName()`은 `PACK.name`을 쓰고, 없으면 예전처럼 `<제목>_v<버전>`(예전 폴더 호환). [폴더에 저장]도 `name`을 그대로 쓴다.
2. **zip 이름을 폴더 이름과 같게**: `<폴더>/<폴더 이름>.zip`. 폴더 맨 위의 `.zip`(예전 `Any-Slide.zip` 포함)은 넣지 않는다.
3. **윈도우 자소 분리 막기**: 제목, 폴더 이름, zip 파일 이름, zip 안의 모든 이름을 NFC로 맞춘다(파이썬 `unicodedata.normalize`). `send-telegram.mjs`도 받는 파일 이름을 NFC로 보낸다.
4. 문서: AGENTS.md, `app/README.md`, 스킬 문서 두 벌(같은 내용), 버전 1.8.0.

Claude가 확인한 것: NFD 제목으로 만든 폴더·zip 이름과 zip 안 34개 이름이 모두 NFC이고 UTF-8 표시가 있음, 틀린 날짜(`2026-02-30`) 거부, 날짜 없는 덱 파일은 날짜 없이 만듦, `--zip-folder`를 다시 돌려도 zip 안에 zip이 없음, 발표 폴더를 헤드리스 Chrome으로 열어 33쪽, 기본 덱 13장 캡처가 수정 전과 같음.

## 지시 사항 (검토만 한다)

- **소스 파일을 고치지 않는다.** 의견과 수정 제안만 보고서에 적는다.
- **Chrome은 실행하지 않는다.** 코드 읽기와 Node·파이썬 격리 실행으로만 확인한다.
- **텔레그램 등 밖으로 아무것도 보내지 않는다.** `send-telegram.mjs`는 실행하지 않는다.
- `decks/`의 파일과 바탕화면은 읽기만 한다. `pack-deck.mjs`를 시험하려면 덱과 그림 폴더를 임시 폴더에 복사하고 `--dest`도 임시 폴더로 준다. 끝나면 만든 폴더와 `decks/생성기록.json` 변경을 되돌린다.

중점적으로 볼 것:
- 날짜 판별(`isDate`, 파일 이름에서 날짜 꺼내기)의 경계값, 날짜가 있을 때와 없을 때 버전 계산·생성 기록
- NFC 처리가 빠진 길: 덱 그림(media) 파일 이름, `--dest` 경로, 생성 기록의 제목 비교, `--zip-folder`에 NFD 폴더나 끝에 `/`가 붙은 경로
- zip에서 맨 위 `.zip`을 빼는 조건(`dp == folder`)이 경로 모양에 따라 어긋나지 않는지
- `packName()`과 [폴더에 저장]의 예전 폴더 호환, `name`에 위험한 글자가 들어갈 수 있는지
- 문서와 코드가 맞는지
