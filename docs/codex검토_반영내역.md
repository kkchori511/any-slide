# Codex 검토 반영 내역

검토 원문: `docs/codex결과_코드검토.md`. 번호는 그 문서의 문제 번호다.

## 고친 것

| 번호 | 내용 | 조치 |
| --- | --- | --- |
| 1 | 불러온 스티커 좌표로 HTML 속성 주입 | `sanitize()`가 허용 필드만 새 객체로 복사하고 숫자는 범위를 제한한다. 이미지는 `assets/` 안 파일만 허용한다. 악성 덱으로 확인했고 DOM에 남지 않는다. |
| 2 | 불러오기 실패가 기존 덱을 손상 | `Object.hasOwn`으로 형태를 판정하고, 후보 덱을 검증하고 렌더링해 본 뒤에만 교체한다. 빈 파일이나 `{}`는 오류로 처리한다. |
| 3 | 저장 실패와 손상을 숨김 | 저장 실패 시 화면 아래에 경고를 띄운다. 손상된 저장값은 `any-slide-deck-v1-broken`에 남기고 알린다. |
| 4 | 마지막 입력 후 200ms 이내 종료 시 저장 공백 | `pagehide`와 `visibilitychange`에서 즉시 저장한다. |
| 5 | 버튼의 Enter/Space가 슬라이드 이동으로 처리됨 | 버튼과 링크에서는 이동 단축키를 쓰지 않는다. 썸네일을 실제 버튼으로 바꿨다. |
| 6 | 스티커가 화면 밖으로 나가 회수 불가 | 이동은 절반 이상 슬라이드 안에 남도록, 크기는 40~1920px로 제한한다. |
| 7 | pointercancel과 캡처 해제 시 정리 없음 | up, cancel, lostpointercapture를 같은 마무리 함수로 처리한다. |
| 8 | 긴 글자가 다음 칸을 침범 | 글자 칸마다 최대 높이를 두고, 넘치면 글자 크기를 최대 55%까지 자동으로 줄인다. 본문과 보조 설명은 한 묶음으로 흘러가서 본문이 길면 보조 설명이 아래로 밀린다. 그래도 넘치면 편집 화면에 빨간 점선을 표시한다. |
| 9 | 둥실둥실 옵션 변경 뒤 선택이 해제됨 | 렌더링 전에 선택 번호를 보관했다가 복원한다. |
| 11 | 썸네일과 스티커 패널 접근성 | 썸네일 버튼에 이름과 현재 표시를 달고, 패널 버튼에 이름을 붙이고, 포커스 표시를 추가했다. |
| 12 | 편집 모드 버튼과 E 키가 동작하지 않음 | 해당 버튼과 E 키를 제거하고 발표 버튼 도움말에 Esc 종료를 적었다. |
| 13 | 한글 조합 중 Esc가 편집 필드를 blur | 조합 중(`isComposing`, keyCode 229)에는 앱 단축키를 처리하지 않는다. |
| 기타 | 첫/마지막 장에서 이동 키가 애니메이션을 재시작 | 같은 장이면 다시 그리지 않는다. 발표 중 키 입력도 HUD를 다시 보이게 한다. 최소 배율을 보장하고 사용하지 않는 `@keyframes noop`을 지웠다. |

## 아직 남은 것

- **10. 끝의 줄바꿈 1개 제거**: 의도한 마지막 줄바꿈이 저장 때 사라질 수 있다. 영향이 작아 두었다.
- **실제 브라우저 검증**: Codex는 브라우저를 실행하지 못해 Node 격리 실행으로 확인했다. 한국어 입력기 조합, 전체 화면 진입과 종료, Safari와 Firefox 동작은 직접 써 보며 확인해야 한다.
- **덱 규모**: 썸네일을 매번 다시 만들어서 슬라이드가 수십 장이 넘으면 부분 갱신이 필요하다.

## 재검토(`docs/codex결과_재검토.md`) 반영

실제 Chrome(헤드리스)에서 앱 코드를 그대로 불러와 시나리오별로 확인했다.

| 번호 | 내용 | 조치와 확인 결과 |
| --- | --- | --- |
| N1 | 삭제·초기화 후 화면이 갱신되지 않음 | 덱이 바뀌는 경로는 `go(..., true)`로 다시 그린다. 첫 장 삭제 후 화면이 본문 장으로 바뀌고 썸네일 5개, 초기화 후 제목이 기본값임을 확인. |
| N2 | 앱이 만든 덱이 다시 열리지 않거나 잘림 | 불러올 때 글자를 잘라 내지 않는다. 장 수(300)와 스티커 수(100) 제한은 추가·복제할 때 미리 막는다. 300장 덱과 6,000자 제목이 그대로 다시 열림을 확인. |
| N3 | 크기 조절 뒤 스티커가 다시 사라짐 | 이동과 크기 조절 모두 끝에 위치를 다시 제한하고, 세로는 실제 그려진 높이를 쓴다. 왼쪽 끝에서 줄여도 `x=-20, w=40`으로 절반이 보임을 확인. |
| N4 | 발표 중 숨은 썸네일을 잘못 측정 | 숨은 요소는 측정하지 않고, 편집으로 돌아올 때 썸네일을 다시 맞춘다. 높이는 `offsetHeight`로 재서 등장 애니메이션 영향도 없앴다. 복귀 후 썸네일이 무대와 같은 24.2px임을 확인. |
| N5 | 복구용 보관 실패를 성공으로 안내 | 실패하면 그렇게 알리고 원본을 파일로 내려받을지 묻는다. 저장 성공은 저장 실패 경고만 지운다. 발표 중에는 쪽 번호 옆에 저장 실패를 표시한다. |
| N6 | 인코딩된 경로로 assets 밖을 가리킴 | 스티커 이미지는 앱이 아는 파일 목록에 있는 것만 허용한다. `assets/%2e%2e/…`와 외부 주소가 걸러짐을 확인. |
| 기타 | 입력할 때 슬라이드 전체를 다시 맞춤 | 입력 중인 칸만 맞춘다. 썸네일을 눌러 이동해도 키보드 포커스를 유지한다. |

기본 6장은 수정 전후 캡처를 픽셀 비교해 글자 영역이 같음을 확인했다.

## 1차 수정 검토(`docs/codex결과_1차수정검토.md`) 반영

사용자가 8건 모두 승인했다. 실제 Chrome(헤드리스)에서 시나리오별로 확인했다.

| 번호 | 내용 | 조치와 확인 결과 |
| --- | --- | --- |
| 1 | 미리 보기 페이지에서 덱의 `</script>`가 스크립트를 끊음 | 미리 보기 전에 앱과 같은 검증을 거치고, 넣는 문자열의 `<` `>` `&`와 줄 구분 문자를 `\u` 표기로 바꾼다. `</script>`가 든 코드 장이 글자 그대로 그려짐을 확인. |
| 2 | 이모지 뒤 글자 서식 오류 | 선택 위치와 같은 단위(UTF-16)로 세고, 여러 글자로 된 이모지는 통째로 고르게 경계를 넓힌다. 😀A👨‍👩‍👧B에서 A만, 가족 이모지는 통째로 적용됨을 확인. |
| 3 | 표 칸의 `\|`가 칸을 잘못 나눔 | `|` 앞의 `\` 개수가 홀수인지 짝수인지로 구분자를 판단한다. `a\|b`, `끝\`, `\\|` 등이 저장 후에도 그대로임을 확인. |
| 4 | 서식 안의 끝 줄바꿈과 블록 뒤 글 | 끝 줄바꿈을 실제 글자로 판단하고, 블록 뒤에 이어지는 글도 줄바꿈으로 읽는다. 코드·번호 칸도 같은 규칙. `**A\n**`, `<div>첫줄</div>뒤`, 빈 줄, 코드 끝 줄바꿈 왕복 확인. |
| 5 | A+/A−가 연속 적용되지 않음 | 누를 때마다 현재 값을 읽고 도구 줄 표시를 갱신한다. 두 번 눌러 120%, 표시도 120% 확인. |
| 6 | 가운데가 기본인 칸의 왼쪽 정렬 | 형태의 기본 정렬과 다르면 값을 저장한다. 큰 한 문장에서 왼쪽이 저장되고 다시 그려도 왼쪽, 가운데로 되돌리면 기본값임을 확인. |
| 7 | Tab으로 도구 줄에 가면 사라짐 | 도구 줄로 포커스가 옮겨 가도 편집 칸과 고른 범위를 기억하고, 다시 그려도 같은 버튼에 포커스를 돌려준다. 키보드로 [B]를 눌러 고른 범위만 굵게 됨을 확인. |
| 8 | 스티커 추가 직후 화살표·Delete가 안 됨 | 스티커를 추가하거나 고르면 버튼의 포커스를 푼다. 패널로 추가한 뒤 화살표 10px 이동, Delete 삭제 확인. |

## 2차 수정 검토(`docs/codex결과_2차수정검토.md`) 반영

사용자가 6건 모두 진행을 승인했다. 실제 Chrome(헤드리스)에서 Codex의 재현 방법 그대로 확인했다.

| 번호 | 내용 | 조치와 확인 결과 |
| --- | --- | --- |
| 1 | 끌기 중 장을 바꾸면 다음 장에 저장됨 | 끌기 시작 때 대상 장을 고정하고, 다시 그리기(장 이동 포함) 전에 진행 중인 끌기를 마무리한다. 표지를 끄는 도중 본문으로 넘겨도 표지에만 저장됨을 확인. |
| 2 | 그림을 화살표로 옮기면 화면 밖으로 사라짐 | 그림은 실제 그려진 높이로 위치를 제한한다(마우스·키보드 공통 `clampPos`). 아래 끝에서 가운데가 1080에 멈춤을 확인. |
| 3 | 크기 상한이 없어 다시 열면 달라짐 | 앱과 검증이 같은 최대 크기(`OBJ_MAX`)를 쓴다. 저장 3840 = 다시 열기 3840 확인. |
| 4 | 묶음 상자를 작게 줄이면 안쪽 칸이 음수 | 종류별 최소 크기(`objMinSize`)를 끌기와 검증에 함께 쓰고, 안쪽 배치도 0 이하가 되지 않게 한다. 비교 상자가 200×290에서 멈추고 안쪽 폭 100 확인. |
| 5 | 자동 정렬과 같은 정렬을 고르면 저장 안 됨 | 자동 정렬 칸은 직접 고른 정렬을 항상 저장하고 [자동] 버튼으로 되돌린다. 가운데 선택이 긴 글 입력 뒤에도 유지되고 [자동]으로 되돌아감 확인. |
| 6 | 다른 포인터가 끌기를 움직이거나 끝냄 | 처음 누른 포인터만 따르고, 손을 떼기·취소·창 포커스 잃음·장 이동에서 한 번만 마무리한다. 다른 포인터의 이동·떼기를 무시함 확인. |
| 기타 | 보고서의 부가 의견 | 맞춤이 되는 조작에서만 ⌥ 안내 표시, 위치 제한으로 좌표가 바뀌면 보조선 지움, 탭에 선택 상태(aria-selected), 검사 스크립트가 화면 밖 개체 경고. |

## 4차 수정 검토 (v1.4.0 ~ v1.6.0)

검토 원문: `docs/codex결과_4차수정검토.md`. 번호는 그 문서의 문제 번호다.

| 번호 | 내용 | 조치 |
| --- | --- | --- |
| 1, 6 | 비동기 인쇄에서 쪽이 일찍 지워짐, 준비 중 재실행 시 섞임 | `afterprint` 뒤에 정리하고, 신호가 없으면 다음 PDF 시작 때 정리한다. 준비 중에는 [PDF]·[만들기]를 잠그고 고른 장을 시작할 때 고정한다. 3초 초과 시 경고. DOM 대역으로 즉시 반환·연속 실행·신호 없음·3초 초과를 확인했다. |
| 2, 3 | `MEDIA/` 대문자와 제어문자 허용 | 폴더 이름은 소문자 `media/`만, 확장자만 대소문자 허용. 제어문자·앞뒤 공백·확장자 앞 공백 거부. 스크립트도 `isMediaSrc`를 쓴다. 허용 6개·거부 16개 경계값 확인. |
| 4, 5 | 미리 보기 `app/media` 링크가 남거나 다른 덱을 가리킴 | 준비부터 실행까지 한 `try/finally`와 종료 신호 정리. 기존 `app/media`는 이 덱 그림 폴더 연결일 때만 쓰고, 다른 연결·끊어진 연결·실제 폴더면 멈춘다. 가짜 Chrome으로 여섯 경우 확인. |
| 7 | 그림 자리에 폴더가 있으면 덜 만든 발표 폴더가 남음 | 그림은 읽을 수 있는 실제 파일만 통과. 숨김 임시 폴더에서 만든 뒤 이름을 바꾸고, 실패하면 임시 폴더를 지우며 기록하지 않는다. 격리 루트에서 여섯 경우 확인. |
| 의견 5 | 문서 보충 | 스티커의 `media/` 허용과 파일 이름 규칙, 미리 보기·발표 폴더 동작, PDF 기본 이름·3초 대기·확인한 브라우저 범위를 스킬 문서와 README에 적었다. |

남은 것: 사파리·파이어폭스·엣지의 실제 인쇄 동작은 확인하지 않았다. 정보 버튼이 PDF 창을 닫지 않는 점, 입력칸에서 Esc를 두 번 눌러야 창이 닫히는 점은 기존 패널과 같은 동작이라 그대로 두었다.

## 5차 수정 검토 (v1.7.0)

검토 원문: `docs/codex결과_5차수정검토.md`. 이번 단순화([PDF] → [인쇄], 쪽 고르기 창 제거)로 새로 생긴 결함은 없었다.

| 번호 | 내용 | 조치 |
| --- | --- | --- |
| 1 | 인쇄 창이 기다려 주지 않는 브라우저에서 인쇄 중 다시 누르면 앞 작업을 덮어씀 (4차부터 있던 구조) | 고치지 않음(사용자 결정). 크롬은 인쇄 창이 떠 있는 동안 앱을 누를 수 없어 생기지 않는다. 인쇄는 크롬 기준이고, 사파리는 쪽이 잘려서 쓰지 않는다(사용자 확인). 다른 브라우저의 남은 위험으로 둔다. |
