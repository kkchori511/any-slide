# 4차 수정 검토 결과 (v1.4.0 ~ v1.6.0)

## 요약

- `main`(`6a21a74`)과 `skill-ask-date`(`fdc1261`, 검토 시 HEAD)의 변경을 코드 읽기와 Node 격리 실행으로 검토했다.
- 그림 경로의 대소문자 처리 불일치, 제어문자 허용, PDF 연속 실행의 공유 DOM 충돌을 재현했다.
- 미리 보기의 링크 정리·기존 링크 처리에 문제가 있고, 비동기 인쇄 환경에서는 즉시 DOM을 지우는 방식이 위험하다.
- 발표 날짜 지침과 두 스킬 문서는 일치하며, 쪽 번호 파서의 일반 경계값 검사와 819개 범위 왕복 검사는 통과했다.
- 소스·사용자 덱·생성기록은 수정하지 않았고, Chrome 실행·외부 전송도 하지 않았다. 실제 브라우저의 출력 품질과 호환성은 이번 검토에서 확인하지 않았다.

## 문제 목록

### 1. [높음] 비동기 인쇄에서는 인쇄할 DOM과 파일 이름이 너무 일찍 사라질 수 있음

- **위치:** `app/app.js:1246–1255`
- **증상:** `window.print()`가 인쇄 완료 전에 반환하는 환경에서는 인쇄 미리 보기나 PDF가 빈 내용으로 나오거나, 파일 이름이 원래 문서 제목으로 돌아갈 수 있다.
- **근거:** **[정적 확인]** `finally`가 `window.print()` 반환 직후 `document.title`을 복구하고 `printHost`를 비운다. 인쇄 종료 이벤트와 연결된 정리 절차가 없다. **[실행 확인 — 격리]** 실제 `printPdf` 함수를 Node VM의 DOM 대역으로 실행하고, 즉시 반환하는 `print()` 이후 내용을 읽도록 하니 쪽 수 `0`, 제목 `original`이었다. **[추정]** 특정 Safari·Firefox 버전에서 실제로 문제가 발생하는지는 확인하지 않았다. 대역 실행은 비동기 인쇄라는 조건에서의 코드 동작만 입증한다.
- **수정 제안:** 인쇄 전에 `afterprint` 처리기를 등록하고, 인쇄 종료·취소 후 DOM과 제목을 정리한다. `print()` 호출 예외에는 별도 정리를 두며, 인쇄 세션 상태와 함께 관리한다. 단순히 긴 타이머로 지우는 방법은 인쇄 완료를 보장하지 못한다.
- **영향·확인:** PDF 저장 경로 전체에 영향을 준다. 후속 검증에서는 Safari·Firefox·Chrome·Edge에서 저장과 취소, 기본 파일 이름, 재인쇄를 확인해야 한다.

### 2. [중간] `MEDIA/`는 덱 검증을 통과하지만 검사·복사 대상에서 빠짐

- **위치:** `app/deck-spec.js:404–405`, `.claude/skills/slide-deck/scripts/media.mjs:13`, `app/style.css:131`, `app/style.css:297`
- **증상:** `MEDIA/missing.png`를 그림 칸이나 스티커에 넣어도 유효한 덱으로 받아들인다. 그러나 `mediaRefs`는 이를 수집하지 않으므로 빠진 그림 경고와 패키징 중단을 건너뛰고, 그림이 없는 발표 폴더를 성공으로 만든다. 대문자 경로에는 덱 그림용 CSS도 적용되지 않는다.
- **근거:** **[실행 확인 — 격리]** `sanitize`는 그림 칸·스티커의 `MEDIA/a.png`를 유지하지만 `mediaRefs`는 `[]`를 반환했다. 원본 스크립트의 임시 복사본으로 `MEDIA/missing.png`를 패키징하니 종료 코드 `0`이고 출력 폴더에 `media/`가 없었다. 정규식의 `i` 플래그와 `startsWith('media/')`의 차이가 원인이다.
- **수정 제안:** 디렉터리 접두사는 정확히 소문자 `media/`만 받도록 하고 확장자만 대소문자를 허용하는 방식을 추천한다. 또는 검증 단계에서 접두사를 정규화한 뒤 모든 소비자가 같은 규칙을 쓰게 한다. 파일 이름 자체를 소문자로 바꾸면 대소문자를 구별하는 파일시스템에서 다른 파일이 되므로 피한다.
- **영향·확인:** 그림 검사·미리 보기·패키징·화면 스타일에 걸친 문제다. `media/`, `MEDIA/`, 혼합 대소문자와 `.PNG` 조합을 함께 검사한다.

### 3. [중간] URL에서 제거되는 제어문자를 파일 이름으로 허용함

- **위치:** `app/deck-spec.js:404–405`, `.claude/skills/slide-deck/scripts/media.mjs:20`, `.claude/skills/slide-deck/scripts/pack-deck.mjs:101–104`
- **증상:** 파일 이름에 LF·TAB 등이 있으면 검사와 복사는 원래 파일 이름으로 성공해도, 그림 URL은 다른 파일을 가리켜 표시되지 않는다.
- **근거:** **[실행 확인 — 격리]** `media/a\nb.png`, `media/a\tb.png` 모두 `isMediaSrc`가 참이고 `sanitize`도 유지했다. Node의 WHATWG `URL`로 해석한 경로는 둘 다 `media/ab.png`였다. LF가 실제 들어 있는 `a\nb.png` 파일을 임시 그림 폴더에 만들자 패키징은 종료 코드 `0`으로 통과했다. HTML 속성의 `esc()`는 이러한 URL 정규화 차이를 해결하지 않는다.
- **수정 제안:** 파일 이름에서 제어문자(`U+0000–001F`, `U+007F`)를 명시적으로 거부한다. URL에서 정규화되는 앞뒤 공백 등도 정책을 정해 거부하고, 같은 검증 규칙을 검사와 복사에 사용한다.
- **영향·확인:** 그림 칸·스티커 모두 해당한다. 한글·일반 공백·`&`·대문자 확장자는 정상 사례로 유지하고, LF·CR·TAB·NUL과 끝의 줄바꿈을 거부하는지 확인한다.

### 4. [중간] 미리 보기 준비 중 예외·프로세스 중단 시 `app/media` 링크가 남을 수 있음

- **위치:** `.claude/skills/slide-deck/scripts/preview-deck.mjs:37–51`, `:61–64`
- **증상:** 링크를 만든 뒤 출력 폴더 생성이나 임시 프로필 생성이 실패하면 링크와 임시 HTML을 정리하지 않는다. 프로세스가 신호로 종료될 때의 정리도 없다. 남은 링크는 다음 덱의 미리 보기에 영향을 줄 수 있다.
- **근거:** **[정적 확인]** `fs.symlinkSync`는 46행, `mkdirSync`·`mkdtempSync`는 48–49행이고 `try`는 51행에서 시작한다. 이 구간의 예외는 `finally`에 들어가지 않는다. `SIGINT`·`SIGTERM` 처리기도 없다. 반면 Chrome 호출이 일반 예외로 실패하는 경우는 기존 `finally`가 정리한다. 지시에 따라 미리 보기 스크립트는 실행하지 않았다.
- **수정 제안:** 임시 HTML 생성부터 모든 준비와 실행을 하나의 `try/finally`로 감싸고, 생성한 자원만 정리하도록 추적한다. 처리 가능한 종료 신호에도 같은 정리 함수를 연결한다. 강제 종료·전원 중단은 정리를 보장할 수 없으므로 시작 시 잔여 링크를 식별하고 복구하는 절차도 둔다.
- **영향·확인:** 미리 보기 도구에 한정된다. 향후 Chrome을 호출하지 않는 파일시스템 대역 시험으로 출력 경로 오류·프로필 생성 실패·종료 신호를 주고 정리를 확인한다.

### 5. [중간] 기존 `app/media`가 다른 덱을 가리켜도 그대로 미리 보기를 진행함

- **위치:** `.claude/skills/slide-deck/scripts/preview-deck.mjs:41–46`
- **증상:** 이전 덱 링크나 다른 폴더가 `app/media`에 남아 있으면 새 덱 그림 폴더 대신 기존 폴더에서 그림을 읽는다. 이름이 같은 파일이면 다른 그림이 그려져 검토를 오도하고, 이름이 다르면 그림이 빠진다. 끊어진 심볼릭 링크는 또 다른 실패 경로다.
- **근거:** **[정적 확인]** 기존 경로가 있으면 경고만 출력하고 계속한다. `missingMedia`는 새 덱 그림 폴더를 확인하므로 실제로 읽는 기존 폴더의 상태와 다를 수 있다. 끊어진 링크에 대한 `existsSync`는 거짓이어서, 다시 `symlinkSync`하다 `EEXIST`로 실패할 수 있다. 이 코드도 정리용 `try` 밖이다.
- **수정 제안:** `lstat`·`readlink`·실제 경로 비교로 기존 경로를 구분하고, 요청한 그림 폴더와 다르면 덮어쓰지 말고 중단한다. 더 견고한 대안은 미리 보기마다 격리된 앱 폴더를 쓰는 것이다. 공유 `app/media`를 유지하면 동시 실행도 차단한다.
- **영향·확인:** 기존 실제 폴더, 올바른 링크, 다른 덱 링크, 끊어진 링크를 각각 검사한다. 기존 사용자 폴더를 자동 삭제하는 방식은 피한다.

### 6. [중간] PDF 준비 중 재실행하면 선택한 쪽과 실제 출력이 뒤섞임

- **위치:** `app/app.js:1228–1255`, `:1291–1299`, `:1462–1464`
- **증상:** 첫 PDF가 글꼴·그림을 기다리는 동안 다시 PDF를 만들면 두 작업이 하나의 `printHost`를 덮어쓴다. 첫 작업이 두 번째 선택의 쪽을 출력하고 지운 뒤, 두 번째 작업은 빈 DOM을 인쇄할 수 있다. 파일 이름의 쪽 번호도 실제 내용과 달라질 수 있다.
- **근거:** **[정적 확인]** 준비 상태 플래그나 버튼 비활성화가 없고, `makePdf`는 `printPdf` 완료를 기다리지 않는다. **[실행 확인 — 격리]** 실제 PDF 함수 블록을 Node VM에 넣고 글꼴 준비 Promise를 대기시킨 상태에서 `printPdf([0])`, `printPdf([1])`을 연속 실행했다. 대기를 풀자 첫 인쇄는 두 번째 장을 첫 장 이름(`발표_v1_1`)으로, 두 번째 인쇄는 빈 쪽 목록을 두 번째 장 이름(`발표_v1_2`)으로 관찰했다. DOM·인쇄는 대역이며 브라우저 출력 시험은 아니다.
- **수정 제안:** 준비부터 인쇄 종료까지 한 작업만 허용하고 관련 버튼을 비활성화한다. 덱과 선택 목록은 시작 시 스냅샷으로 고정하며, 준비·인쇄 실패를 잡아 사용자에게 알리고 상태를 복구한다. 1번의 인쇄 수명 관리와 함께 고치는 편이 좋다.
- **영향·확인:** 느린 그림·글꼴 환경에서 재실행하거나 덱을 변경하는 경우를 확인한다. 동시 요청이 거절되거나 순서대로 독립 처리되어야 한다.

### 7. [낮음] 그림 경로에 디렉터리가 있어도 사전 검사에 통과해 불완전한 발표 폴더를 남김

- **위치:** `.claude/skills/slide-deck/scripts/media.mjs:20`, `.claude/skills/slide-deck/scripts/pack-deck.mjs:76–77`, `:98–104`
- **증상:** `directory.png`라는 디렉터리가 있으면 그림이 있다고 판단한다. 앱 파일을 복사한 후 그림 복사에서 오류로 종료되어 불완전한 폴더가 남고, 같은 이름으로 재시도하면 기존 폴더 때문에 중단된다.
- **근거:** **[실행 확인 — 격리]** 임시 그림 폴더에 `directory.png/`를 만들자 `missingMedia`는 `[]`를 반환했다. 패키징은 그림 복사에서 종료 코드 `1`로 실패했고 `<제목>_v1/` 폴더는 남았다. 생성기록은 성공 단계에 도달하지 않아 추가되지 않았다.
- **수정 제안:** 사전 검사에서 실제 일반 파일인지와 읽기 가능 여부를 확인한다. 패키징은 임시 출력 폴더에서 완성 후 최종 이름으로 옮기고, 실패하면 이번 작업이 만든 임시 폴더만 정리한다.
- **영향·확인:** 정상 그림·누락·디렉터리·읽기 실패를 검사한다. 이 문제는 유효한 그림 파일 내용이나 확장자 일치까지 검사한다는 뜻은 아니다.

## 확인한 정상 동작과 검토 범위

### 경로·HTML 안전성

- **[실행 확인 — 격리]** `../`, 하위 폴더, 역슬래시, `%` 인코딩, `:`, `?`, `#`, 따옴표, 백틱, 점으로 시작하는 파일 이름, SVG 경로를 거부했다. 이번 범위에서는 상위 경로·외부 URL을 허용하는 우회는 발견하지 못했다.
- 한글·공백·`&`가 있는 그림 파일과 `#`, `&`, 공백이 있는 덱 JSON 이름으로 임시 패키징이 성공했다. 확장자 `.PNG`도 허용한다. 파일시스템별 유니코드 정규화 및 Windows 예약 파일 이름은 실환경 시험을 하지 않았다. 스킬은 덱 전용 그림에 영문 파일 이름을 권장한다.
- **[정적 확인]** 그림 칸(`app/app.js:379`)과 스티커(`:397`)는 큰따옴표 HTML 속성에 넣기 전 `esc()`를 사용한다. `&`, `<`, `>`, `"`를 이스케이프하며, 허용 경로에서 작은따옴표도 거부한다. 고정 형태 그림(`:345`)의 `o.src`는 타입 정의에서 오고, 사용자 `layout`은 좌표·크기·회전·숨김만 복사하므로 이번 변경으로 사용자 경로가 이 비이스케이프 지점에 들어가는 경로는 찾지 못했다.
- 저장소 앱·발표 폴더·JSON 불러오기는 `sanitize`를 거친다. 패널에서 그림 칸을 바꾸거나 스티커를 추가하는 경로는 기존 `STICKERS`를 사용한다. 덱 전용 그림을 패널에서 다시 고르지 못하는 제한은 README에 설명돼 있다.

### 스크립트 격리 실행

- 임시 루트에 원본 `pack-deck.mjs`, `media.mjs`, 앱 코드 파일을 그대로 복사하고, 합성 덱·1픽셀 PNG·빈 `assets/`·`fonts/` 디렉터리로 패키징 경로를 시험했다. 실제 글꼴·전체 에셋을 담은 배포 품질 시험은 아니다.
- `--dest`와 생성기록 경로 모두 임시 루트 안으로 격리했다. 사용자 `decks/`를 읽거나 복사할 필요가 없었으며, 원래 `decks/생성기록.json`은 건드리지 않았다. 모든 임시 시험 폴더는 종료 시 제거했다.
- 누락 그림은 폴더 생성 전에 종료 코드 `1`로 중단했다. **[정적 확인]** 참조가 있는데 그림 폴더 자체가 없는 경우도 같은 누락 검사에서 중단하고, 참조가 없으면 그림 폴더 없이 패키징할 수 있다. `--media`는 기본 그림 폴더 경로를 대체한다.
- `preview-deck.mjs`는 실행하지 않았고 링크 동작은 코드만 읽었다. Chrome 대용 실행파일로 우회 실행하는 시험도 하지 않았다.

### 인쇄 CSS·대기

- **[정적 확인]** 인쇄 시 화면 숨김, 페이지 크기·여백·배경 색 조정, 그림자 대신 테두리 규칙은 `@media print` 안에 있다. 화면용 `.slot img[src^="media/"]`의 모서리·그림자 추가는 의도된 공통 스타일 변화다.
- `printHost`는 절대 위치로 왼쪽 화면 밖에 있어 일반 흐름에서 빠지고 `aria-hidden`이다. `.print-page` 관련 화면 규칙은 인쇄용 하위 요소에 한정된다. 편집·발표·썸네일의 기존 레이아웃을 직접 바꾸는 추가 규칙은 찾지 못했으나 실제 화면 비교는 하지 않았다.
- `makeSlide`에 `animate:false`를 주고 글꼴·배경·그림 로드 또는 오류를 최대 3초 기다린 뒤 `fitText`를 호출한다. 이미지 `complete`는 로드 실패도 포함하므로 그림 존재·출력 성공을 보장하지 않는다.
- **[정적 확인]** 3초 뒤 늦게 준비된 글꼴은 `printHost`를 다시 맞추지 않는다(`app/app.js:1497`의 `loadingdone`은 현재 장·썸네일만 처리). 따라서 느린 환경에서는 글꼴 대체·글자 넘침이 남을 수 있다. 이를 별도 확정 결함으로 세지는 않았지만, 제한 시간 초과 시 경고·재시도 또는 준비 완료 후 출력 정책을 권한다.
- 요청서에 적힌 기존 Chrome PDF·캡처 검증은 선행 작업자의 보고로만 취급했으며 이번에 재검증한 결과로 보지 않았다. 브라우저 인쇄 설정과 실제 용지·배경 처리도 이번 검토에서 확정하지 않았다.

### 쪽 고르기·문서

- **[실행 확인 — 격리]** `1-5, 8`, 역방향 범위, 중복, `~`, 선행 0을 처리했다. 빈 입력, 0, 범위 밖, 음수, 소수, 지수 표기, 잘못된 구간, 매우 큰 수를 거부했다. 1–13장에 대해 가능한 모든 단일 구간 819개를 `parsePages → pagesToText → parsePages`로 왕복시켜 일치를 확인했다.
- **[정적 확인]** 유효한 입력은 번호 버튼 선택에 반영되고, 번호 버튼은 입력을 정렬·압축해 갱신한다. 잘못된 입력은 버튼 선택을 비우고, [만들기] 때 오류 메시지를 표시한다. 공백·쉼표만 반복된 구분자는 허용하는 현재 동작이다.
- **[실행 확인 — 격리]** PDF 패널 함수의 DOM 대역 시험에서 2장을 선택한 뒤 장 수를 1장으로 줄여 재개방하자 범위 밖 선택은 제거되고 입력은 `1`이 됐다. **[정적 확인]** 선택이 전부 제거되면 현재 장을 넣는다. 장 번호 기준 유지이므로 중간 삽입·삭제 뒤에도 같은 내용의 장을 추적하는 기능은 아니다.
- **[정적 확인]** PDF 열기는 스티커·설정·정보 패널을 닫고, 스티커·설정 열기는 PDF를 닫는다. 정보 버튼은 PDF를 닫지 않아 두 패널이 함께 열릴 수 있다(`app/app.js:1424–1426`). 입력·버튼 포커스에서 Esc는 첫 번째에 blur만 하고 두 번째에 패널을 닫는다(`:1349–1353`). 기존 패널 동작과의 일관성은 있으나 사용성 개선 여지는 있다. 낮은 우선순위 의견이며 별도 결함 수에는 포함하지 않았다.
- 파일 이름은 발표 폴더에서는 `packName()`을 사용하고, 저장소 앱에서는 `Any-Slide`를 쓴다. 일부 선택은 쪽 번호가 붙으며, 모든 쪽을 일부 모드로 고르면 장 수 비교 때문에 접미사를 생략한다. 제목은 `text` 속성으로 지정하므로 HTML 주입 지점은 아니다. 비동기 환경에서 제목 복구 시점은 1번에 해당한다.
- 두 스킬 문서는 바이트 단위로 같고, 발표 날짜 확인·노션 그림 저장·참조·PDF 안내가 코드 및 AGENTS.md와 대체로 맞는다. 다만 스킬의 스티커 목록 아래 설명(`.claude/skills/slide-deck/SKILL.md:239`, `.codex/skills/slide-deck/SKILL.md:239`)은 `img`의 `media/` 허용만 명시하므로 스티커도 같은 경로를 허용한다는 코드 정책을 덧붙이면 명확하다. README의 PDF 이름 설명도 저장소 앱 기본값을 보충하면 좋다.

## 의견 (우선순위 순서)

1. **PDF 인쇄 수명과 중복 실행을 함께 정리한다(1·6번).** 인쇄 종료 전에 DOM·제목을 지우지 않고, 준비부터 종료까지 하나의 작업으로 관리한다. 실제 Safari·Firefox의 동작은 후속 브라우저 시험으로 판정한다.
2. **그림 경로 규칙을 하나로 통일한다(2·3번).** 소문자 `media/` 접두사, 대소문자를 허용하는 확장자, 제어문자 거부를 공통 정책으로 권한다. 폴더·파일 누락을 검사하기 전에 같은 규칙을 적용한다.
3. **미리 보기 링크의 소유·정리 범위를 명확히 한다(4·5번).** 다른 덱을 그린 결과가 정상 캡처로 검토되지 않게, 충돌 시 중단하고 준비 단계 실패도 정리한다.
4. **패키징 실패가 불완전한 최종 폴더를 남기지 않게 한다(7번).** 일반 파일 사전 검사와 임시 폴더에서 완성 후 이동하는 방식을 권한다.
5. **사용 안내를 실제 보장 범위에 맞춘다.** 3초 대기 초과, 저장소 앱 PDF 이름, 스티커의 `media/` 허용을 보충한다. 인쇄 설정이 모든 브라우저에서 그대로 적용된다는 표현은 지원 환경 검증 뒤 정한다.

이 문서는 검토와 수정 제안만 담았다. 제안 반영·커밋·외부 전송은 하지 않았다.
