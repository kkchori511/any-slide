## 요약

- 빌드 없이 사용하는 소규모 발표 도구로 구조가 단순하고, 6종 템플릿의 기본 에셋 배치는 기준 PNG와 대체로 잘 맞는다.
- 우선 수정할 문제는 JSON 좌표값을 통한 HTML 속성 주입과, 실패했다고 알린 불러오기가 현재 덱·자동 저장을 이미 바꾸는 문제다.
- 저장 실패를 사용자에게 알리지 않으며, 버튼 키보드 조작·스티커 선택 유지·화면 밖 스티커 복구에도 결함이 있다.
- 실제 소스를 Node.js의 격리 환경에서 실행하여 로직 문제를 재현했다. 브라우저 실행에 실패하여 브라우저 실측·IME·전체 화면·포인터 실기 검증은 완료하지 못했다.
- 소스·에셋은 수정하지 않았다. 저장한 프로젝트 파일은 이 보고서뿐이다.

- **[추정/실기 미확인]**: 발생 조건과 근거는 있으나 실제 브라우저·장치에서 증상까지 확인하지 못했다.
- 실행용 보조 파일과 비교 이미지는 `/private/tmp/`에만 두었다. 원래 브라우저 프로필과 앱의 실제 localStorage는 사용하지 않았다.

## 문제 목록

### 1. 높음 — 불러온 스티커 좌표로 HTML 속성 주입 가능

- **상태:** [격리 실행 확인: HTML 문자열 주입], 실제 브라우저에서 이벤트 실행은 미확인.
- **위치:** `app/app.js:110`, `app/app.js:120`, `app/app.js:160`, `app/app.js:171`.
- **증상:** `sanitize()`는 스티커의 `src`만 문자열인지 확인한다. `x`, `y`, `w`는 검증·이스케이프 없이 `innerHTML`에 넣을 `style="..."` 안으로 들어간다. JSON 파일을 공유하는 사용 경로에서 이벤트 속성이나 임의의 태그를 삽입할 수 있다.
- **재현/근거:** 스티커의 `x`를 아래 값으로 지정하면 `slideHTML()`이 반환하는 HTML에 독립적인 `onpointerover` 속성이 만들어진다. 실제 코드에서 따옴표를 벗어나는 것을 확인했다.

  ```json
  {
    "slides": [{
      "type": "body",
      "stickers": [{
        "src": "assets/face.png",
        "x": "0\" onpointerover=\"globalThis.__reviewMarker=1;//",
        "y": 0,
        "w": 220
      }]
    }]
  }
  ```

- **영향:** 신뢰하지 않는 덱 파일이 앱 문맥에서 스크립트를 실행할 수 있는 XSS 경로다. 브라우저별 `file://` 보안 정책에 따른 추가 접근 범위는 검증하지 않았다.
- **수정 제안:** 스티커 객체를 허용 필드만 복사하여 새로 만들고 `Number.isFinite()`와 좌표·크기 범위를 검증한다. 가능하면 DOM 노드를 생성한 뒤 `style.left/top/width`에 검증된 숫자만 대입한다. `src`도 허용한 로컬 에셋 목록으로 제한하거나 외부 이미지 허용 정책을 명시한다. 텍스트와 `src`에는 이미 `esc()`가 있어, 이번 문제는 검증되지 않은 숫자 필드가 핵심이다.

### 2. 높음 — 불러오기 실패가 기존 덱을 보존하지 않으며 잘못된 상태까지 저장

- **상태:** [격리 실행 확인].
- **위치:** `app/app.js:112`, `app/app.js:119`, `app/app.js:138`, `app/app.js:413`.
- **증상:** 검증과 렌더링을 끝내기 전에 `deck`을 교체하고 저장 타이머를 건다. 이후 렌더링이 실패하면 경고만 띄우며 이전 덱으로 되돌리지 않는다.
- **재현:** 기존 제목을 바꾼 뒤 `{"slides":[{"type":"toString"}]}`을 불러온다. `TYPES[s.type]`가 상속된 함수를 유효한 타입으로 오인한다. `type.items.map`에서 TypeError가 발생하고 불러오기 실패 경고가 나온다. 그런데 현재 덱은 이미 교체되었으며, 예약된 저장을 실행하면 `toString` 타입이 저장된다. 재실행 시에도 정규화가 이를 통과시켜 초기 화면 렌더링을 막을 수 있다.
- **별도 재현:** `{}`처럼 JSON 문법만 맞는 다른 파일은 `sanitize()`가 기본 6장 덱을 반환하여 오류 없이 기존 작업을 대체한다. 빈 덱 파일도 같은 동작이다.
- **수정 제안:** `Object.hasOwn(TYPES, s.type)`로 타입을 판정한다. 유효하지 않은 최상위 구조·슬라이드는 명시적인 검증 오류로 처리한다. 후보 덱의 전체 검증과 렌더링 준비가 성공한 뒤 상태 교체와 저장을 한 번에 수행한다. 오류 때 현재 덱과 이전 저장값을 보존한다.

### 3. 중간 — 자동 저장 실패와 저장 데이터 손상을 조용히 숨김

- **상태:** [격리 실행 확인: 저장 오류 무통지], [정적 확인: 로드 오류 무통지].
- **위치:** `app/app.js:103`, `app/app.js:107`, `app/app.js:128`.
- **증상:** localStorage의 용량 초과·차단·파싱 실패가 사용자에게 보이지 않는다. 사용자는 자동 저장된 것으로 오해할 수 있다. 손상된 저장값을 읽으면 기본 덱을 보여 주고, 이후 편집은 원래 저장값을 새 내용으로 덮어쓸 수 있다.
- **재현/근거:** 저장소 대역의 `setItem()`이 예외를 던지도록 한 뒤 실제 저장 콜백을 실행했다. 예외는 삼켜졌고 오류 알림·저장 실패 상태가 없었다. 로드에서도 모든 예외를 같은 방식으로 무시한다.
- **수정 제안:** 저장 중/완료/실패와 마지막 성공 시각을 표시한다. 실패 시 JSON 내보내기를 안내한다. 손상된 원문을 복구용으로 보관하고, 기본값으로 열었다는 사실을 알린다.

### 5. 중간 — 툴바 버튼의 Enter·Space 키가 슬라이드 이동으로 처리됨

- **상태:** [격리 실행 확인].
- **위치:** `app/app.js:334`, `app/app.js:341`, `app/app.js:343`.
- **증상:** 단축키 제외 대상에 `BUTTON`이 없다. 버튼에 포커스를 놓고 Enter 또는 Space를 누르면 문서 핸들러가 `preventDefault()`하고 다음 슬라이드로 이동하여 버튼의 기본 키보드 활성화를 방해한다.

- **수정 제안:** 버튼·링크·체크박스·메뉴 등 상호작용 요소의 키 이벤트는 전역 탐색에서 제외한다. 발표 탐색 단축키의 적용 영역을 별도로 정하고 편집 모드와 분리한다.

- **위치:** `app/app.js:160`, `app/app.js:197`, `app/app.js:203`, `app/app.js:394`, `app/app.js:396`, `app/index.html:56`.
- **증상:** 썸네일은 클릭 가능한 div지만 탭 포커스·역할·선택 상태가 없다. 스티커도 포커스/이름/키보드 이동·크기 조절이 없다. 패널의 이미지 버튼은 이미지 `alt=""`이고 별도 접근성 이름도 없어 선택할 소품을 알기 어렵다. 현재 슬라이드 HUD는 `aria-hidden`이다.
- **수정 제안:** 썸네일을 이름 있는 버튼이나 적절한 목록 패턴으로 구성하고 현재 항목을 알린다. 스티커 버튼에 이름을 붙인다. 객체 선택·방향키 이동·크기 조절·삭제가 가능한 별도 경로와 포커스 표시를 제공한다. 발표 슬라이드 변경을 필요에 맞게 알린다. 텍스트 편집 필드에는 이미 CSS 포커스 표시가 있다.

### 12. 낮음 — 편집 모드 버튼·E 안내와 실제 동작 불일치

- **상태:** [격리 실행 확인] 및 [정적 확인].
- **위치:** `app/index.html:13`, `app/app.js:351`, `app/app.js:368`.
- **증상:** 안내는 편집 모드 켜기/끄기(E)이지만 편집 중 버튼과 E는 아무 변화가 없다. 발표 중에는 버튼이 숨겨지고 E도 편집 모드로 돌리지 않는다.
- **재현:** 편집 상태에서 버튼 핸들러와 E 키 핸들러를 실행해도 `mode='edit'`가 유지된다. 코드에 별도의 비편집 미리보기 상태도 없다.
- **수정 제안:** 현재 가능한 동작에 맞게 버튼 이름·도움말을 바꾸거나, 실제 편집 잠금/미리보기 상태와 일관된 토글을 구현한다.

### 13. 중간 — 한글 조합 중 Escape가 편집 필드를 강제로 blur할 가능성

- **상태:** [정적 확인], 실제 한국어 IME 충돌은 [추정/실기 미확인].
- **위치:** `app/app.js:334`, `app/app.js:336`.
- **증상/근거:** 일반 입력 필드는 `typing` 검사로 대부분의 탐색 단축키를 피하지만, Escape는 그보다 먼저 처리하여 즉시 blur한다. `isComposing`이나 조합 상태 검사가 없다. 조합 취소용 Escape를 앱이 먼저 처리할 수 있다.
- **수정 제안:** 조합 중에는 앱 단축키를 건너뛰고, `compositionstart/end`와 필요시 `isComposing`을 함께 고려한다. macOS/Windows 한국어 입력기에서 Escape·Enter·방향키·마지막 조합 직후 슬라이드 전환을 실제 검증한다. 일반 한글 입력이 모두 깨진다는 뜻은 아니다.

## 검토한 기능별 긍정 사항과 남은 검증

- **편집:** 일반 `input` 이벤트에서는 해당 덱 필드만 갱신하고 썸네일을 지연 갱신한다. stage 전체를 교체하지 않아 기본적인 커서 유지 방향은 적절하다. 반면 배경·글꼴·형태·애니메이션 변경은 stage를 교체하므로 선택 범위 복원은 별도 고려가 필요하다.
- **contenteditable 지원:** MDN의 호환성 원자료는 `plaintext-only`를 Chrome 51+, Safari 5+, Firefox 136+에서 지원한다고 기록한다. 따라서 최신 Firefox에서 무조건 편집이 안 된다는 지적은 맞지 않는다. Firefox 135 이하를 지원한다면 기능 검사와 대체 편집 방식이 필요하다. 지원 여부와 별개로 Enter·Shift+Enter·붙여넣기·IME DOM 표현은 실제 대상 버전에서 검증해야 한다. 근거: [MDN 호환성 원자료](https://github.com/mdn/browser-compat-data/blob/main/html/global_attributes.json), [MDN contenteditable 설명](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/contenteditable).
- **스티커:** 캡처와 화면 배율 보정이 있으며 너비 최소 40px를 둔다. pointerdown에서 애니메이션을 제거하므로 조작 중 계속 둥실거리는 것은 막지만, 손을 뗀 뒤에는 그 DOM에서 애니메이션을 복원하지 않는다. 슬라이드를 다시 렌더링하면 설정에 따라 재생된다. 이를 편집 중 정책으로 둘지 명시하면 좋다.
- **발표:** 전체 화면 실패를 catch하여 발표 화면 자체는 유지한다. Esc 종료와 `fullscreenchange` 복귀, 키보드/클릭 탐색, resize의 `fit()` 경로는 있다. 실제 전체 화면 승인/종료, Safari의 API 지원 차이, 다중 화면 및 창 크기 변경 실측은 미완료다. 36px보다 작은 가용 크기에서 배율이 음수가 될 가능성도 있어 최소값 방어가 좋다.
- **커서:** 2200ms 뒤 body에 idle을 주고 마우스 이동 시 해제한다. 다만 스티커 위는 `.present .sticker { cursor:none }`이어서 idle 이전에도 숨긴다. 키보드 이동은 idle을 깨우지 않으므로 마우스를 쓰지 않을 때 HUD가 다시 보이지 않는다. 의도한 발표 정책인지 결정할 부분이다.
- **애니메이션:** `go()`가 stage를 다시 생성하므로 이동 때 재생되는 구조다. 애니메이션 끄기는 `no-anim`과 `!important`, 동작 줄이기는 `prefers-reduced-motion` 규칙이 있어 처리 경로가 있다. 실제 computed style·타이밍은 미확인이다. 이미 첫/마지막 장인데 이동 키를 눌러도 재렌더링하여 같은 장의 애니메이션을 재시작한다.
- **보안:** 일반 텍스트와 `src`의 따옴표는 `esc()`로 처리한다. `font`는 `style.setProperty()`에 넣으므로 그 문자열 자체를 HTML 속성 탈출 문제로 분류하지 않았다. 외부 `src` 허용은 별도로 이미지 네트워크 요청/프라이버시 정책을 정해야 한다.
- **코드 품질:** `@keyframes noop`(`style.css:130`)은 사용처가 없고 E 키 분기(`app.js:351`)는 실질적으로 빈 동작이다. 이것보다 저장·검증·선택 상태 문제의 우선순위가 높다. 매 이동마다 모든 썸네일을 재생성하는 구조는 덱이 커질 때 비용이 커지므로 실제 큰 덱으로 측정한 후 부분 갱신을 고려한다.

## 개선 의견: 우선순위 순서

1. **덱 스키마와 안전한 불러오기부터 정리한다.** 허용 타입·문자열 필드·유한 좌표·이미지 소스·슬라이드/스티커 개수·파일 크기를 검증한다. 스키마 버전을 두고 실패 시 기존 덱을 그대로 유지한다. HTML 속성 주입 경로를 먼저 없앤다.
2. **저장 신뢰성을 사용자에게 보이게 한다.** 저장 상태와 실패 이유, 종료 전 flush, 복구 가능한 이전 버전, 내보내기 안내를 제공한다. 삭제/초기화/불러오기에도 복구 지점을 남기면 좋다.
3. **선택 상태와 조작 경로를 안정화한다.** 스티커 ID, 선택 보존, 객체 목록, 화면 중앙 복구, 키보드 이동/크기 조절, 취소 이벤트 정리를 우선한다. 드래그 한 번을 실행 취소 단위로 묶는다.
4. **텍스트 편집의 범위를 명확히 한다.** 끝 개행과 조합 입력을 보존하고, 상자 넘침을 알려 준다. 글자 크기·행간·상자 높이 등 기본 편집 옵션을 제공한다. 현재 본문의 “자료를 자유롭게 배치”라는 예시는 실제 텍스트·이미지 상자의 자유 배치 기능보다 기대가 크므로 기능 또는 문구를 맞춘다.
5. **편집/미리보기/발표와 접근성을 정돈한다.** 버튼 단축키 충돌을 없애고, 실제 동작에 맞는 편집 모드 안내, 이름 있는 스티커 버튼, 포커스 가능한 썸네일, 선택 상태 전달을 제공한다.
6. **표현과 성능은 그 다음에 고정한다.** 기준 글꼴, 말풍선 글자 굵기, 애니메이션 중 편집 정책을 정한다. 큰 덱에서 썸네일 전체 재생성 비용을 측정하고 필요한 부분만 갱신한다. 발표 자료 재사용을 위해 이미지/PDF 출력은 추후 기능으로 고려할 수 있다.

## 확인하지 못한 부분

- 헤드리스 Chrome을 임시 프로필로 실행했으나 종료 코드 134로 끝났다. 사용 가능한 연결 브라우저 목록은 비어 있었고 일반 Chrome 연결 시도도 시간 초과했다. 원인까지 단정하지 않는다.
- 따라서 Chrome/Safari/Firefox에서의 실제 페이지 로드, 전체 화면/Esc, 한국어 IME, 붙여넣기/개행, 포인터 캡처·터치 취소, OS별 폰트, reduced-motion 실작동, 커서와 HUD 타이밍을 브라우저 실기로 확인하지 못했다.
- 6종의 **완성된 브라우저 렌더링 화면**과 기준 PNG의 시각 비교는 미완료다. PNG 직접 관찰과 소스 좌표 기반 에셋 비교만 수행했다. 글자 위치·크기의 완전한 일치를 보증하지 않는다.
- XSS의 속성 탈출과 잘못된 상태 저장은 격리 실행으로 확인했지만, 악성 이벤트가 실제 브라우저에서 실행되는 장면 및 실제 사용자 데이터 손실은 재현하지 않았다.
- 읽기 전후 소스 3개 SHA-256을 비교하여 불변을 확인했다. 검토용 파일을 앱에 추가하거나 앱을 수정하지 않았다.
