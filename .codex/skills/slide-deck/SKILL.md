# 슬라이드 덱 만들기

사용자가 준 발표 내용을 덱 JSON 파일로 만들고, 그 덱으로 **발표 폴더**를 만든다. 발표 폴더의 `Any-Slide.html`을 열면 덱이 바로 열려서 편집하거나 발표할 수 있다. 저장소의 앱(`app/Any-Slide.html`)에서는 **[불러오기]** 로 덱 파일을 연다.
앱은 범용이다. 발표 내용은 덱 파일에만 넣고 앱 코드에는 넣지 않는다.

## 순서 (반드시 이 순서로)

### 1. 사전 조사: 만들기 전에 먼저 묻는다

아래를 사용자에게 묻는다. 이미 받은 자료(노션 등)에서 알 수 있는 것은 "이렇게 이해했다"고 적어 확인만 받는다. 질문은 한 번에 짧게 묶어서 한다.

| 항목 | 덱에 반영하는 곳 |
| --- | --- |
| 발표 종류와 목적 (강의, 특강, 보고, 연수 …) | 구성, 형태 선택 |
| 청중 (대상, 수준, 인원) | 말투, 용어 수준, 글 양 |
| 시간과 분량 (분, 장 수) | 장 수 (대략 1분에 1장) |
| 분위기: 활동적 ↔ 차분 | `settings`의 전환·글자 등장·그림 등장·둥실둥실 |
| 색감 (아이보리, 세이지, 블루그레이, 그 밖의 색) | `bg`, 강조 글자 색 |
| 발표자 이름·소속 | 표지와 종료 장의 `name` |
| 참고 자료 (노션, 문서, 링크) | 내용의 출처 |
| 참여 요소 (질문, 활동, 실습) | 설명·큰 한 문장 장 배치 |
| **저장 경로** (기본: 바탕화면 `~/Desktop`) | 발표 폴더를 만들 곳 |
| **발표 컴퓨터** (이 맥북 / 윈도우) | 윈도우면 6단계에서 zip과 텔레그램 전송을 여쭤봄 |

분위기에 따른 기본값:
- **활동적**: `transition: "slide"` 또는 `"zoom"`, `textAnim: "fly"`, `imgAnim: true`, `float: true`
- **보통**: `transition: "fade"`, `textAnim: "fly"`, `imgAnim: true`, `float: true` (앱 기본)
- **차분**: `transition: "fade"`, `duration: 0.6`, `textAnim: "fade"` 또는 `"none"`, `imgAnim: false`, `float: false`

### 2. 구성안과 그림 제안

장별 구성안(번호, 형태, 제목 한 줄)을 보여 준다. 함께 **정말 필요한 그림만** 제안한다.
- 기존 스티커와 캐릭터로 충분하면 새 그림을 제안하지 않는다.
- 제안할 때는 "몇 번 장에, 무엇을, 왜"를 표로 적는다. 다른 색 배경이 필요하면 그것도 여기에 넣는다.
- 사용자가 수락한 그림만 다음 단계에서 만든다. 수정 요청이 오면 반영해 다시 보여 준다.

### 3. 그림 만들기 (수락한 것만)

그림은 Codex의 이미지 생성으로만 만든다. 스타일 규칙은 `docs/핵심브리프_스티커에셋.md`이고 4번 프롬프트 블록을 그대로 쓴다.
- **Codex라면**: 이미지 생성 기능으로 직접 만든다.
- **Claude라면**: 그림을 그리지 못하므로 herdr의 Codex 창에 맡긴다. `herdr pane list`에서 `agent`가 `codex`인 창을 찾아 `herdr pane send-text <창> "<요청>"` 후 `herdr pane send-keys <창> Enter`로 보낸다. 요청에는 브리프 경로, 만들 대상, 저장 경로, 끝나면 결과를 적을 파일을 넣는다. 결과 파일이 생길 때까지 기다린다.
- 저장: `app/assets/generated/sticker_<이름>.png`, 1254x1254 투명 PNG.
- 만든 뒤 `app/deck-spec.js`의 `STICKERS`에 `{ src, w, name, group: 'extra' }`로 추가한다. 새로 만든 그림은 항상 스티커 패널의 **[추가]** 탭(`group: 'extra'`)에 하나씩 넣는다. [기본] 탭 8개는 바꾸지 않는다.
- 이 문서의 스티커 표에도 적고, 이미지를 직접 열어 체크리스트(브리프 7번)를 확인한다.

### 4. 덱 작성과 발표 폴더

1. `decks/YYYY-MM-DD_<제목>.json`(날짜는 발표일, 공백은 `_`)을 아래 형식과 **레이아웃 원칙**에 맞춰 쓴다. 이 파일이 원본이다.
2. 5단계 검사와 미리 보기를 통과하면 발표 폴더를 만든다.
   ```
   node .claude/skills/slide-deck/scripts/pack-deck.mjs decks/<덱 파일> --title "<슬라이드 제목>" --dest <저장 경로>
   ```
   - 폴더 이름은 `<제목>_v<버전>`이다. 버전은 **같은 제목으로 덱을 만든 횟수**이고 `decks/생성기록.json`에 자동으로 기록된다(같은 경로에 폴더가 있는지와 상관없다).
   - 폴더 안: `Any-Slide.html`(여는 파일), 앱 파일, 그림, 글꼴, 덱 JSON(`<제목>_v<버전>.json`), 덱을 바로 여는 `deck-data.js`.
   - 발표 폴더는 저장 공간을 따로 써서 다른 발표 폴더의 편집 내용과 섞이지 않는다.
   - 제목 앞의 점은 뺀다(숨김 폴더가 되지 않게). 버전을 직접 정해야 하면 `--version N`.
   - 생성 기록이 깨져 있으면 덮어쓰지 않고 멈춘다. 사용자에게 알리고, 기록을 고치거나 `--version N`으로 기록 없이 만든다.
   - 발표 폴더에서 고친 내용은 그 컴퓨터 브라우저에 저장된다. 다른 컴퓨터로 옮기기 전에 앱의 **[폴더에 저장]**(크롬·엣지)을 누르면 폴더 안 덱에 써지고, 옮긴 컴퓨터에서는 더 최근에 고친 쪽(폴더 또는 그 브라우저)이 열린다. 보고할 때 이 점을 짧게 알린다.

### 5. 검사와 미리 보기

- `node .claude/skills/slide-deck/scripts/check-deck.mjs <덱 파일>` → `✘`이면 고친다. `⚠ 넘침`은 글을 줄이거나 장을 나눈다. `⚠ 비어 보임`은 형태를 바꾼다.
- `node .claude/skills/slide-deck/scripts/preview-deck.mjs <덱 파일> <출력 폴더>` → 장마다 PNG를 **직접 열어 본다**. 빈 공간이 많은 장, 글자 겹침, 스티커가 글자나 캐릭터를 가리는지 확인한다.

### 6. 보고와 윈도우 발표 준비

- 발표 폴더 경로, 장 수와 구성(한 줄씩), 사용자가 채워야 할 자리, 여는 방법(폴더의 `Any-Slide.html`)을 짧게 알린다.
- **윈도우에서도 발표할지 묻는다.** 사용자가 허락할 때만 아래를 한다. 묻지 않고 보내지 않는다.
  1. zip 만들기: `node .claude/skills/slide-deck/scripts/pack-deck.mjs --zip-folder <발표 폴더>` → 폴더 안에 `Any-Slide.zip`(압축을 풀면 `<제목>_v<버전>` 폴더, 한글 이름은 UTF-8)
  2. 텔레그램 다다비서봇(@sec_dada_bot)으로 보내기: `node .claude/skills/slide-deck/scripts/send-telegram.mjs <발표 폴더>/Any-Slide.zip --caption "<제목> v<버전>"`
     - 봇 설정은 `~/projects/hwp-telegram-assistant/.env`(BOT_TOKEN, ALLOWED_CHAT_ID)를 읽는다. 토큰은 출력하거나 기록하지 않는다.
     - 봇으로는 50MB까지 보낼 수 있다. 처음이거나 의심스러우면 `--whoami`로 봇 이름만 먼저 확인한다.
  3. 윈도우에서는 zip을 풀고 `Any-Slide.html`을 Edge나 Chrome으로 연다.
  - zip에서는 `.DS_Store`, `._*`, `Thumbs.db`, `desktop.ini`, `.git`만 뺀다.

## 레이아웃 원칙: 화면을 꽉 차고 보기 좋게

사용자는 주로 Claude가 넣은 내용으로 발표한다. 장마다 화면이 비어 보이지 않게 **내용에 맞는 형태**를 고른다.

| 내용이 이렇다면 | 이 형태 |
| --- | --- |
| 요점 1개를 강하게 | `statement` 큰 한 문장 |
| 나란한 요점 2~4개 (특징, 장점, 준비물) | `cards` (count 2~4) |
| 순서가 있는 과정 2~4단계 | `steps` (count 2~4) |
| 두 가지 비교 (전/후, 장/단점, A/B) | `compare` |
| 항목과 값이 짝인 목록 (코드표, 용어 정리) | `table` |
| 코드, 주소, 명령어 | `code` |
| 그림이 핵심인 설명 | `image` |
| 친근하게 풀어 주는 말, 질문 던지기 | `explain` 말풍선 |
| 위에 안 맞는 일반 설명 (3~5줄) | `body` |

- `body`는 3줄 이상일 때만 쓴다. 1~2줄이면 `statement`나 `explain`으로 바꾼다.
- 한 장에 요점 하나. 5줄이 넘거나 카드 4개가 넘으면 장을 나눈다.
- 앱은 글이 적으면 칸에 맞게 키우고(본문 최대 1.5배), 많으면 줄인다(최소 55%). 그래도 비거나 넘치면 형태를 바꾼다.
- 같은 형태가 3장 넘게 이어지지 않게 섞는다. 챕터 A와 B는 번갈아 쓴다.
- 강조는 아껴 쓴다: 장마다 굵게나 색 1~2곳.

### 표·상자 정렬

- 표의 머리 줄, 카드·단계·비교 상자의 제목은 **가운데**가 기본이다.
- 내용은 앱이 자동으로 정렬한다.
  - 짧은 글(2줄 이내, 줄마다 14자 이내)은 가운데
  - 긴 글은 왼쪽
  - 글머리표(•, -)나 번호(1.)로 시작하는 목록은 짧아도 왼쪽
- **나란히 놓인 상자는 정렬을 하나로 통일한다.** 같은 장의 카드·단계·비교 상자 내용과 표의 각 열은 앱이 묶음으로 정렬한다: 하나라도 긴 글이나 목록이면 모두 왼쪽, 모두 짧으면 모두 가운데.
- 그래서 덱을 쓸 때 같은 장의 상자들은 글 길이와 형식(목록인지 문장인지)을 비슷하게 맞춘다. 한 상자만 길면 묶음 전체가 왼쪽이 되므로, 가운데로 보이고 싶으면 모두 짧게 쓴다.
- 자동 정렬을 바꿔야 할 때만 `styles`의 `align`을 쓴다(그 상자만 바뀌므로 통일이 깨지지 않게 묶음의 모든 상자에 같이 준다).

## 덱 형식

```json
{
  "bg": "ivory",
  "font": "",
  "settings": { "transition": "fade", "duration": 0.5, "textAnim": "fly", "imgAnim": true, "float": true },
  "slides": [
    { "type": "cover", "title": "제목 첫 줄\n둘째 줄", "sub": "한 줄 소개", "name": "발표자", "stickers": [] },
    { "type": "cards", "title": "핵심 세 가지", "count": 3, "c1t": "첫째", "c1": "설명", "c2t": "둘째", "c2": "설명", "c3t": "셋째", "c3": "설명" },
    { "type": "body", "title": "제목", "body": "• **중요한** 요점\n• {{blue:파란 글자}}", "sub": "보조 설명",
      "styles": { "body": { "scale": 1.1, "align": "left", "lh": 1.6 } },
      "stickers": [{ "src": "assets/generated/sticker_체크.png", "x": 1500, "y": 330, "w": 220, "rot": -10, "flip": false, "float": true }] }
  ]
}
```

- `bg`: `ivory`(기본), `sage`, `bluegray`
- `font`: 비우면 페이퍼로지. 다른 글꼴은 사용자가 원할 때만.
- `settings`:
  - `transition`: `none`, `fade`, `slide`, `zoom`, `rise`
  - `duration`: 0.2~1초
  - `textAnim`: `fly`, `fade`, `none`
  - `imgAnim`, `float`: true/false
- 장마다 `transition`을 따로 줄 수 있다. 예: 챕터 장만 `"zoom"`.
- 줄바꿈은 `\n`. 글머리표는 `• `를 직접 쓴다.
- **글자 서식 표기**:
  - `**굵게**`, `__밑줄__`, `==형광펜==`
  - `{{red:색 글자}}`. 색은 `red`, `blue`, `green`, `orange`, `gray`
  - 표기 글자를 그대로 쓰려면 앞에 `\`를 붙인다.
  - `code`와 `num` 칸은 표기를 해석하지 않는다.
- `styles`: 칸 전체의 `scale`(0.5~2), `align`(`left`/`center`/`right`), `lh`(줄 간격 1~2.4). 꼭 필요할 때만 쓴다.
- `layout`: 형태의 개체를 장마다 옮기거나 바꾼 값. 아래 "개체 배치" 참고. 꼭 필요할 때만 쓴다.
- 규칙의 원본은 `app/deck-spec.js`(형태 `TYPES`, 스티커 `STICKERS`, 검증 `sanitize`)다. 이 문서와 다르면 그 파일이 맞다.

## 개체 배치 (`layout`)

형태의 그림과 글상자는 모두 개체다. 사용자는 앱에서 끌어 옮기고, 크기를 바꾸고, 회전하고, 삭제할 수 있다. 덱에서는 장마다 `layout`에 바뀐 값만 적는다.

```json
"layout": { "hero": { "x": 1050, "y": 260, "w": 700, "rot": -5 }, "name": { "hidden": true } }
```

- `x`, `y`는 왼쪽 위, `w`, `h`는 폭·높이(글상자의 `h`는 칸 높이, 그림은 `w`만), `rot`는 회전, `hidden: true`는 숨김이다.
- 형태를 바꾸면 그 장의 `layout`은 지워진다.
- 기본 배치가 잘 맞으므로 덱을 만들 때는 거의 쓰지 않는다. 그림을 가리는 글을 피하거나, 필요 없는 장식을 숨길 때만 쓴다.

| type | 개체 id |
| --- | --- |
| `cover`, `end` | `title`, `sub`, `name`, `hero`(캐릭터와 소품) |
| `body` | `title`, `main`(본문+보조 설명), `face` |
| `explain` | `title`, `bubble`(말풍선과 글), `char` |
| `compare` | `title`, `L`, `R` |
| `cards` | `title`, `c1` … `c4` |
| `steps` | `title`, `s1` … `s4`, 화살표 `a1` … `a3` |
| `statement` | `qmark`(따옴표 장식), `main`, `spark` |
| `code` | `title`, `codebox`, `sub` |
| `table` | `title`, `table` |
| `image` | `title`, `slot`(그림 칸), `main` |
| `chapterA` | `num`, `title`, `sub`, `char` |
| `chapterB` | `num`, `title`, `sub`, `props` |

## 형태 표

글자 수는 한 줄 기준 대략값(페이퍼로지, 한글)이다.

| type | 용도 | 칸 | 권장 분량 |
| --- | --- | --- | --- |
| `cover` | 표지 (오른쪽에 캐릭터와 소품) | `title`, `sub`, `name` | 제목 2줄 이내·줄당 9자, 소개 1~2줄 |
| `body` | 일반 본문 | `title`, `body`, `sub` | 제목 1줄·25자, 본문 3~5줄·줄당 30자 |
| `explain` | 캐릭터가 말풍선으로 설명 | `title`, `bubble` | 말풍선 2~3줄·줄당 17자 |
| `compare` | 2단 비교 | `title`, `leftTitle`, `left`, `rightTitle`, `right` | 소제목 1줄·12자, 내용 3~5줄·줄당 16자 |
| `cards` | 카드 2~4개 (`count`) | `title`, `c1t`·`c1` … `c4t`·`c4` | 카드 제목 1줄, 내용 1~3줄 (3개면 줄당 11자) |
| `steps` | 단계 2~4개 (`count`) | `title`, `s1t`·`s1` … `s4t`·`s4` | 단계 이름 1줄, 설명 1~3줄 |
| `statement` | 큰 한 문장 (제목 없음) | `quote`, `sub` | 한 문장 1~2줄·줄당 18자 |
| `code` | 코드·주소 상자 | `title`, `code`, `sub` | 코드 8줄 이내 |
| `table` | 표 (`table`: 줄은 `\n`, 칸은 `\|`, 첫 줄이 머리) | `title`, `table` | 6줄·4칸 이내 |
| `image` | 그림+설명 (`img`: 허용된 그림 경로) | `title`, `img`, `body`, `sub` | 설명 2~4줄 |
| `chapterA` | 장 구분 (오른쪽 아래 캐릭터) | `num`, `title`, `sub` | 번호 `01` 형식, 제목 1줄·17자 |
| `chapterB` | 장 구분 (오른쪽 위 소품 테두리) | `num`, `title`, `sub` | 번호 `01` 형식, 제목 1줄·14자 |
| `end` | 마무리 (오른쪽에 캐릭터와 소품) | `title`, `sub`, `name` | 제목 2줄 이내 |

구성 요령:
- 표지 1장 → (장이 여럿이면) 챕터 → 내용 장들 → 종료 1장.
- 장 번호는 `01`, `02`처럼 두 자리.

## 스티커

좌표는 1920x1080 슬라이드 기준이다.
- `x`, `y`는 스티커 왼쪽 위, `w`는 폭(px)이고 높이는 이미지 비율대로 정해진다.
- `rot`는 회전 각도(-180~180), `flip`은 좌우 뒤집기, `float`는 둥실둥실이다.

스티커 패널은 **[기본]** 8개와 **[추가]**(덱을 만들며 새로 생성한 그림) 두 탭이다.

| --- | --- | --- | --- |
| `assets/generated/sticker_반짝이.png` | 노란 반짝이 | 180~260 | 기본 |
| `assets/generated/sticker_별.png` | 노란 별 | 180~240 | 기본 |
| `assets/generated/sticker_체크.png` | 초록 체크 | 180~240 | 기본 |

## 지킬 것

- 사전 조사와 그림 제안을 건너뛰지 않는다. 사용자가 "바로 만들어"라고 하면 그때만 생략한다.
- 사용자가 준 사실, 숫자, 이름을 바꾸거나 지어내지 않는다. 확인이 필요한 내용은 보고할 때 따로 적는다.
- `decks/`의 파일은 사용자 발표 자료다. 기본으로 git에 올리지 않는다(`.gitignore`). 올릴지는 사용자가 정한다.
- 앱 코드(`app/`)는 덱을 만들려고 고치지 않는다. 새 형태가 필요하면 사용자에게 먼저 제안한다.
