# 슬라이드 덱 만들기

사용자가 준 발표 내용을 `decks/` 폴더의 덱 JSON 파일로 만든다. 사용자는 앱(`app/index.html`)의 **[불러오기]** 로 이 파일을 열어 바로 편집하거나 발표한다.
앱은 범용이다. 발표 내용은 덱 파일에만 넣고 앱 코드에는 넣지 않는다.

## 순서

1. **내용 파악**: 발표 주제, 청중, 분량(장 수), 발표자 이름을 확인한다. 모르는 것은 추측하지 말고 묻거나 자리 표시 문구를 둔다.
2. **구성안**: 내용이 길거나 구성이 애매하면 슬라이드별 한 줄 요약(형태와 제목)을 먼저 보여 주고 확인받는다. 짧고 분명하면 바로 만든다.
3. **덱 작성**: 아래 형식과 형태 표에 맞춰 `decks/YYYY-MM-DD_<제목>.json`을 쓴다. 파일 이름의 제목은 한글 그대로, 공백은 `_`.
4. **검사**: `node .claude/skills/slide-deck/scripts/check-deck.mjs <덱 파일>` 실행. `✘`이면 고친다. `⚠ 넘침`은 글을 줄이거나 슬라이드를 나눈다. `⚠ 자동으로 작아짐`은 괜찮지만 많으면 나눈다.
5. **미리 보기**: `node .claude/skills/slide-deck/scripts/preview-deck.mjs <덱 파일> <출력 폴더>`로 장마다 PNG를 만들고 **직접 열어 본다**. 글자 겹침, 스티커가 글자나 캐릭터를 가리는지, 빈 칸이 남았는지 확인한다.
6. **보고**: 덱 파일 경로, 장 수와 구성(한 줄씩), 사용자가 채워야 할 자리, 여는 방법(앱 [불러오기])을 알린다.

## 덱 형식

```json
{
  "bg": "ivory",
  "font": "",
  "anim": true,
  "slides": [
    { "type": "cover", "title": "제목 첫 줄\n둘째 줄", "sub": "한 줄 소개", "name": "발표자", "stickers": [] },
    { "type": "body", "title": "슬라이드 제목", "body": "• 첫째 요점\n• 둘째 요점", "sub": "보조 설명",
      "stickers": [{ "src": "assets/generated/sticker_체크.png", "x": 1500, "y": 330, "w": 220, "float": true }] }
  ]
}
```

- `bg`: `ivory`(기본), `sage`, `bluegray`
- `font`: 비우면 페이퍼로지. 다른 글꼴은 사용자가 원할 때만.
- `anim`: 등장 애니메이션. 기본 `true`.
- 줄바꿈은 `\n`. 글머리표는 `• `를 직접 쓴다. 다른 서식(굵게, 색)은 없다.
- 각 슬라이드는 자기 형태가 쓰는 칸만 채운다. 다른 칸은 화면에 안 나온다.
- 규칙의 원본은 `app/deck-spec.js`(형태 `TYPES`, 스티커 `STICKERS`, 검증 `sanitize`)다. 이 문서와 다르면 그 파일이 맞다.

## 형태 표

글자 수는 한 줄 기준 대략값(페이퍼로지, 한글)이다. 넘으면 앱이 글자를 자동으로 줄이고(최소 55%), 그래도 넘치면 편집 화면에 빨간 점선이 뜬다.

| type | 용도 | 칸 | 권장 분량 |
| --- | --- | --- | --- |
| `cover` | 표지 (오른쪽에 캐릭터와 소품) | `title`, `sub`, `name` | 제목 2줄 이내·줄당 9자, 소개 1~2줄·줄당 22자 |
| `body` | 일반 본문 (오른쪽 아래 작은 얼굴) | `title`, `body`, `sub` | 제목 1줄·25자, 본문 5줄 이내·줄당 34자, 보조 설명 1~2줄 |
| `explain` | 캐릭터가 말풍선으로 설명 | `title`, `bubble` | 제목 1줄, 말풍선 2~3줄·줄당 19자 |
| `chapterA` | 장 구분 (오른쪽 아래 캐릭터) | `num`, `title`, `sub` | 번호 `01` 형식, 제목 1줄·17자, 설명 1~2줄·줄당 30자 |
| `chapterB` | 장 구분 (오른쪽 위 소품 테두리) | `num`, `title`, `sub` | 번호 `01` 형식, 제목 1줄·14자, 설명 1~2줄·줄당 27자 |
| `end` | 마무리 (오른쪽에 캐릭터와 소품) | `title`, `sub`, `name` | 제목 2줄 이내·줄당 9자 |

구성 요령:
- 표지 1장 → (장이 여럿이면) 챕터 → 본문/설명 → 종료 1장.
- 챕터 A와 B는 번갈아 쓰면 단조롭지 않다. 장 번호는 `01`, `02`처럼 두 자리.
- 한 장에 요점 하나. 본문이 5줄을 넘으면 나눈다.
- 강조하거나 친근하게 풀어 줄 말은 `explain`(말풍선)으로.

## 스티커

좌표는 1920x1080 슬라이드 기준, `x`, `y`는 스티커 왼쪽 위, `w`는 폭(px), 높이는 이미지 비율대로. `float: true`면 둥실둥실 움직인다.

| src | 내용 | 권장 w |
| --- | --- | --- |
| `assets/generated/sticker_반짝이.png` | 노란 반짝이 | 180~260 |
| `assets/generated/sticker_별.png` | 노란 별 | 180~240 |
| `assets/generated/sticker_체크.png` | 초록 체크 | 180~240 |
| `assets/generated/sticker_화살표.png` | 파란 오른쪽 화살표 | 220~300 |
| `assets/generated/sticker_하트.png` | 빨간 하트 | 180~240 |
| `assets/generated/sticker_말풍선.png` | 빈 흰 말풍선 (글자 못 넣음) | 260~360 |
| `assets/face.png` | 캐릭터 얼굴 | 160~260 |
| `assets/hero-props.png` | 캐릭터와 소품 7종 | 400~600 |

- 목록에 없는 경로는 앱이 버린다.
- 글자 칸과 캐릭터 위에 올리지 않는다. 본문 슬라이드는 오른쪽 빈 영역(x 1300~1700, y 300~800)이 무난하다.
- 장마다 0~2개. 꾸밈이 내용보다 눈에 띄면 안 된다.

## 새 그림이 필요할 때

내용을 설명할 그림이 기존 스티커로 부족하면 새로 만든다. 스타일 규칙은 `docs/핵심브리프_스티커에셋.md`이고, 생성 때 그 문서 4번 프롬프트 블록을 그대로 쓴다.

- **Codex라면**: 이미지 생성 기능으로 직접 만든다.
- **Claude라면**: 그림을 그리지 못하므로 herdr의 Codex 창에 맡긴다. `herdr pane list`에서 `agent`가 `codex`인 창을 찾아 `herdr pane send-text <창> "<요청>"` 후 `herdr pane send-keys <창> Enter`로 보낸다. 요청에는 브리프 경로, 만들 대상, 저장 경로, 끝나면 결과를 적을 파일을 넣는다. 결과 파일이 생길 때까지 기다린다.
- 저장: `app/assets/generated/sticker_<이름>.png`, 1254x1254 투명 PNG.
- 만든 뒤 `app/deck-spec.js`의 `STICKERS`와 위 스티커 표에 추가하고, 이미지를 직접 열어 체크리스트(브리프 7번)를 확인한다.

## 지킬 것

- 사용자가 준 사실, 숫자, 이름을 바꾸거나 지어내지 않는다. 확인이 필요한 내용은 보고할 때 따로 적는다.
- `decks/`의 파일은 사용자 발표 자료다. 기본으로 git에 올리지 않는다(`.gitignore`). 올릴지는 사용자가 정한다.
- 앱 코드(`app/`)는 덱을 만들려고 고치지 않는다. 새 형태가 필요하면 사용자에게 먼저 제안한다.
